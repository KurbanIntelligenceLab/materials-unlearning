# Bounding Retraining Equivalence and the Deletion Floor in Materials Machine Unlearning

**Anonymous authors**

## Abstract

In materials machine learning, closely related retained structures can sustain accurate property predictions even after removing a specific record, rendering post-deletion prediction error an ambiguous metric for machine unlearning. To resolve this ambiguity, we define the *deletion floor* as the expected target loss under a specified retraining procedure at the deleted request. Standard indistinguishability constraints yield a sharp interval bounding an update's target loss around this baseline reference. Theoretically, a conditional neighbor bound links a low deletion floor directly to retained fit, prediction regularity, and local label agreement, while an exact ridge identity isolates residual fit from the prediction change induced by record deletion. Empirically, controlled redundancy sweeps show an ≈8× drop in median normalized retraining loss when one retained relative remains after deletion. Across two distinct fitting regimes in a paired Materials Project study, the lower-floor regime also exhibits a larger prediction change on more than 50% of the shared requests. Systematic comparisons against approximate updates and the original model decouple deliberate target suppression from preserved overall model utility. Consequently, request-level unlearning evaluations should report reference loss, prediction change, and retained utility together, interpreting post-deletion accuracy against what retraining itself leaves behind.

## Code and reproducibility

This repository provides the Python implementations, saved numerical evidence, and Lean proofs accompanying the paper.

## Quick start

Use Python 3.10 or newer and run commands from the repository root:

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m materials_unlearning.paired --out runs/paired
```

The paired analysis runs from the included result files, without downloading data or training a model. It checks the paired requests and writes `runs/paired/summary.json`. Saved evidence under `results/` is not overwritten by the documented commands.

## Package

Source code is available under `src/materials_unlearning/`, and results are stored under `results/`. Local datasets belong in `data/`.

Use `python -m materials_unlearning.<module> --help` for command options. `results/files.json` records SHA-256 checksums for results and local input files. Command modules can be imported without starting an analysis or writing output.

## Local data

Data are excluded from version control and package distributions. The data-dependent commands expect:

| Local file | Purpose |
| --- | --- |
| `data/mp20_full.npz` | 44,344 structures with 134 descriptors, targets, and material identifiers |
| `data/mp20_graphs.npz` | Graph cache for neural training, aligned with descriptor-cache identifiers |
| `data/mp20_snapshot.json` | Dataset selection, database version, and proxy contributor-field metadata |

Exact replay requires the original cache matching the checksums in `results/files.json`. Descriptor caches use non-object NumPy arrays and are loaded with pickling disabled. Graph caches contain pickled dictionaries; load only trusted, locally generated graph caches. For cached inputs, `--limit` selects the same leading rows in the corpus and graph cache. The graph cache is only needed for graph-model training; the neural descriptor analysis uses saved neural losses plus the descriptor cache.

For a new dataset, install the structure-processing dependencies:

```sh
python -m pip install -e '.[materials]'
python -m materials_unlearning.prepare_data --help
python -m materials_unlearning.cache_features --help
```

`prepare_data --source mp` reads a Materials Project API key from `MP_API_KEY`; `--source cifs` accepts local structures and a target CSV. A new database export can differ from the original snapshot and is not an exact replacement for the submitted data. Keep credentials in the environment, outside source files.

## Replay commands

Controlled redundancy generates its own synthetic datasets:

```sh
python -m materials_unlearning.controlled --out runs/controlled
```

With the descriptor cache available, run the materials analyses:

```sh
python -m materials_unlearning.ridge --out runs/ridge_standard
python -m materials_unlearning.ridge --features 8192 --lam 1e-8 --diagnostic-requests 300 --out runs/ridge_high_capacity
python -m materials_unlearning.operating_points --corpus data/mp20_full.npz --out runs/operating_points
python -m materials_unlearning.neural_geometry --out runs/neural
```

The standard ridge setting uses 2,048 features and regularization 1e-6; the high-capacity setting uses 8,192 features and regularization 1e-8. Full ridge calculations and repeated fitting can require substantial memory and time. The controlled sweep also performs repeated fits; it is not a quick installation check.

For neural training, install `python -m pip install -e '.[neural]'` and supply both `--backend cgcnn` and `--graphs data/mp20_graphs.npz` to the neural fitting command. Inspect its `--help` before launching training.

## Analysis conventions

The ridge reference holds the original training split's normalization, bandwidth, and random features fixed. The neural descriptor analysis is exploratory and conditional on one training seed; request-bootstrap intervals do not quantify training-seed uncertainty.

The `script_sha256` fields identify the original generating code. File checksums are listed in `results/files.json`.

Wheels contain the Python package. Source distributions also contain the saved numerical evidence, proof sources, and release tools.
